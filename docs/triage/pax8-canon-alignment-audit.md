# Pax8 Canon Alignment Audit — Triage List

**Status:** Draft inventory — needs Rovo follow-up to verify against Pax8 canon.
**Date:** 2026-05-16
**Author:** Triage pass on pax8-cli@docs/triage-v0.1.0-launch-prep
**Why:** The MRR-naming surprise (Bret Pittenger) and the recommendations/Seat-Gap surprise (Randall Ellis / Rovo) revealed that the CLI has been inventing logic and vocabulary in places where Pax8 already has canonical definitions. This is a sweep of the rest of the CLI surface to identify everything else that needs to be cross-checked.

This file is a **triage list**, not a verdict. Each row records what the CLI does today and flags whether it's likely to diverge from Pax8 canon; the actual canon-check is a separate Rovo task. Risk ratings are a first-pass gut call from someone who hasn't checked the source-of-truth definitions yet:

- **High** — the CLI applies a name or interpretation that a Pax8 stakeholder is likely to read with a specific canonical meaning that differs from the CLI's usage. These are the candidates most likely to mirror Bret's MRR feedback or Randall's seat-gap feedback.
- **Medium** — derived/aggregated math that's plausibly fine, but isn't the API's own number. Worth confirming whether Pax8 has a canonical formulation (especially around bucketing, normalization, and currency).
- **Low** — direct passthroughs, presentational labels, or vocabulary that's commonly understood and well-disclaimed in code.

The existing per-field disclaimers in code (e.g. the renewals "this is not Revenue at Risk Predictor" docstring, the recommendations module-level STAX/OE comment, the help-text "Equivalent to Partner Gross MRR" assertion) are *claims* the CLI makes about Pax8 canon — Rovo should confirm each of those claims is still accurate, not just review the un-disclaimed code.

## What this triage did NOT cover

- The internals of the `MockPax8Client` demo data (`packages/core/src/mock/`) — same risks would apply if mock data uses different numbers than real-API surfaces, but that's a separate "demo-mode realism" audit.
- The agent-facing skill manifest (`packages/claude-skill/skill.md`) — Bret's MRR feedback came through the skill surface; the manifest's own phrasing of MRR / renewals / recommendations is worth a parallel sweep but wasn't included here.
- The `README.md` "Metric definitions" block and `docs/UX_GUIDE.md` flag table — both make canon claims and should be re-verified alongside this list, not separately.
- Specific numeric thresholds inside the cross-sell engine's "minimum-seats-to-flag" gates (the `< 10` cutoff in `findSeatGaps`, the `>= 5000` "💰 That's $X/yr waiting to be captured" celebration line). These are UX magic numbers, not metric definitions, so I left them off.
